## 文本匹配（玩家视角）

判据是**玩过原版的人，能不能在这一版里重拾原版体验**。

冲突时按项目总原则：**游戏体验 > 还原原版 > 其他**。

### E1 认得出（原版覆盖）

- [ ] 原版范围内（293 个脚本；Steam 新增的 35 个后日谈 / 追加剧本不核对）**逐场未承载行 = 0**
      —— 每一行原版文本都能在某一格读到。口径是 **按 CCS 聚合**（一个 CCS 被多个脚本切片，
      单脚本覆盖率无意义）。⚠️ 这是**必要条件、不是充分条件**（见下条「差分」）
- [ ] **差分必须「覆盖」回去，禁止「追加」**：Steam 删改一段原版时往往不留空，而是**写一段摘要／替代文本占住那些格子**。
      这类站点必须**先删掉替代文本、再落原版**（走 `scene_slices.json` 的替换通道或表内 `drop`），
      **不得**在别处再插一份原版而把摘要留在屏上——那会让玩家把同一件事读两遍
      （一遍精简且无必要、一遍详细），属**严重困扰**级缺陷。
      反例（本判据的来由）：`CCD2002B_EN` k=248–256 的自撰摘要 ↔ 原版 `CCD2002` #854–889（34 行整场 H）
- [ ] **「未承载行 = 0」与「零双写」两条必须同时成立**：只查前者对差分是**结构性盲区**
      （它看不见顶替的那段摘要还在不在屏上）。差分候选可由机械扫描枚举
      （P 型＝替代段紧邻缺失段；「现状即双写」＝缺失段已被 `insert` 补回而替代段仍在），
      **枚举结果只给置信度**——每一处都要人工读原文裁定「是同一件事的摘要」还是「Steam 新增的另一场戏」，
      后者不还原版、不得删（`op:drop` 不可批量套用）
- [ ] **不以「有没有 CG」判定 H／血腥场景是否还原**：无 CG 的纯文本场景对 CG 锚点回查是
      **结构性盲区**，必须走未承载行的语义核查
- [ ] 允许的缺口只有两类：① 已登记在 [restoration-targets.md](restoration-targets.md) 的工作项；
      ② 已裁定「不就地插入、改走选项分支」的站点（如 `CCB2017`）

### E2 不卡眼睛（排版与演出）

- [ ] **控制标记三族一律保留**：
      翻页族＝正文格尾 `%K%P` ／ 纯清框族＝独立 `%P` + 正文 ／ 整屏清空族＝独立 `%P` + 连排 `%N`。
      处理 `%N`/`%P` 的**唯一目的**是消掉**非原版带来的多余空行、空翻页**；
      判据是「**这一组在原版对应位置是否存在**」，不是「看起来像空行」——**逐格判，不按组批量删**
- [ ] 不出现「堆字 / 整段不翻页」：删格后前后两屏不得挤进同一个未清屏文本框
- [ ] **`15` 结构照抄 Steam**：产物里每条 `15` 都紧贴某个 `14`（作设名或清框），**不得有游离的 `15`**；
      相邻的 `15` 不得被压掉（`python script/audit/verify_ws2_conventions.py` 的连跑 ⊆{1,2} 断言）
- [ ] **还原插入的每一句都要独立成页**（带页断符，与原版惯例一致）：判据是**原版该句本就占一页**，
      **与插入段长短无关**——21 句和 1 句都是缺陷，长短只影响严重程度，不影响是否算缺陷
- [ ] `op:drop` 全部站点复核：只允许删**非原版的多余正文或多余空行**，不得删三族成员
      （⚠️ 写盘器：`drop` 现在**删整格** —— `14` 连同它的设名/清框 `15`，带「不改动任何存活格名字框」
      的守卫；见 [file-formats.md](file-formats.md)「0x15」）
- [ ] 同屏不出现同一句显示两遍（先查该格是否 `src:"zhfill"` 复用邻格中文）
- [ ] 空白拍与原版节奏一致，长连排 `%N` 组不得减拍

### E3 读得通（连贯性）

- [ ] **台词切分的可接受度（裁定）**：Steam 部分段落英文句数更多、并新增演出或把一句语音切成几段，
      故本项目**按英文句的语义划分点**对中文做了切分。视觉小说中"适当的语句零散化"
      **可接受**——只要上下文连贯、意境相同，不要求每一片都是完整句子成分。
      仅下列四种情形算缺陷（判时必须写明命中哪一条）：
      ① 切分**破坏词或专名**；② 某片**只剩标点或语气字**；
      ③ **上下文连贯或意境被破坏**；④ 一句的两半之间**插进了别的台词/说话人/新译正文**
- [ ] 无悬空：还原插入不得「插半句」——逗号断头、指代无所指均算（如 `CCB2007`、`CCC3025`）
- [ ] 无自相矛盾：新译与还原段不得互相打脸（直译撞句）
- [ ] **译注可以出现（裁定 · 不得误杀）**：原版中文本地化文本自带的「（译注：…）」「※…」一类注释，
      属**原版既有内容**，照搬进成品不算缺陷。仅当**本项目自撰**的说明混进台词框时才处理
- [ ] **选项 / 菜单译法不要求逐词一致（裁定）**：同一英文动作在不同语境（旅行菜单 / 分支标签 / 正文台词）
      用不同中文**是正常的**。判时必须回到该选项所在的界面与上下文：**用语风格一致**即可；
      只有**同屏或同族两个不同英文动作撞成同一个中文**（玩家无法区分）才算缺陷
- [ ] 格间源行号单调不减、无倒序、无整段错挂（`script/audit/audit_inline.py`）
- [ ] **范围排除**：民汉文本**既有**的语病、错字不属本项；新增或本批改写的文本的错误计入

### E4 动线完整

- [ ] 分支与选项全部可达，选项支两侧文本成对、无悬空选项
- [ ] 还原段引用的 CG / 背景 / 蒙版 / 语音齐备，不卡死引擎
- [ ] 实机：至少一位测试者完整通关一条角色线（见「实机测试清单」）

### 判级（逐站点归零制）

**缺陷以「站点」为单位管理，不以比例管理。** 一个逗号断头、一处名字框串人、一句没翻页，对玩家都是完整的一次出戏——
第 30 处和第 1 处同样成立。因此：

| 项 | 门槛 | 说明 |
|---|---|---|
| **E1 覆盖 / E2 排版 / E3 连贯 / E4 动线** | **全部 pass / fail** | 每一处缺陷都要么修掉，要么**逐条明确裁定**为下述两种之一，否则不得关闭 |

一个站点只有两种出路：

1. **已登记工作项**——写进 [restoration-targets.md](restoration-targets.md)，注明缺口范围与计划；
2. **经裁定的原版既有 / 豁免**——写明判据（例：该效果在原版本就存在、译注属原版本地化、该场按裁定不还原），
   **由项目负责人逐条确认**，不接受"批量归类后整体放行"。

**禁止的判定方式**：用覆盖率、平均分、"某桶 N/M 场可放行"这类**聚合指标**作为放行依据。
聚合数字只能用于安排工作量，**不能用于判定质量**
（统计器本身有已知漏报，"没测出来"不等于"没问题"）。

## 落地门槛：全量语义校对

**落地（写盘）前，必须保证所有将被显示的文本「完全正常」。** 三条硬要求：

1. **规则不能代替判断，只能提供置信度。** 结构四条、哨兵、严丝合缝、逐格内容比对 —— 都是**机械判据**，
   职能是**圈定要判的位置**与给出信心，**不能定案**。
   反例：`CCD2002B_EN` 的 `k=252–259` 把被删的**整场 H** 压成 8 格概述，
   **所有机械检查全过**，语义上却让玩家把同一件事读两遍（一遍精简、一遍详细）。
   > 「产物 == 表」的内容比对是**同义反复**，只验了写盘器忠实，**没验内容对不对**。
2. **必须 293 场全量语义校对**，且**对着落地后的真实产物**读 —— 落地前的结论一律作废。
   - 载体：逐场生成「玩家连续读到的台词流」，每场一份、供连续通读；
   - **唯一判据**：玩家**连着读**，这一句在**位置上**读得通吗（顺序 / 指代 / 说话人 / 有无同义两遍 / 有无悬空标点）；
   - 未逐字通读的场次一律**不得放行** —— **必须补完**；
   - 本批**改动区域逐格回读**（插入段 / 差分改取 / 逐格修补）。
3. **机械检查是独立的第二道**：两者**同向才算数**；任一不同向 → 退回**单独语义判断**，不用阈值/规则兜。

**顺序**：②③ 落表 → 重跑管线（机械全绿） → **293 场全量语义校对** → 修订 → 才谈「可发布」。
形态识别（改写 / 整段删+新写 / **压缩概述**）见 [lessons-learned.md](lessons-learned.md) 「内容还原的三种差分形态」。
