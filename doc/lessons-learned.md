## 仍未解决 / 待验证

### 立绘站位没有标定

原版 x 全是 `6.25 = 800/128` 的整数倍（原版屏幕 1/128 的栅格，34 个取值），Steam 只有 6 档站位 `{0, ±275, ±400}`（+`±399/400` 三人位外侧），必然多对一；**哪个簇对应哪一档，四种配对法互相矛盾**（最可信的「源侧帧唯一 → 配对强制」组只有 3 个主簇、且都没有主导档位）。`tool/wsc2ws2.py` 的 `steam_x()` 只是**单调启发式**，不是标定结果。**精确标定需要按对白锚点对齐两侧帧**（两引擎的 `14` 对话 id 逐项相等，是天然锚）—— **尚未做**。

**已证伪、不要再走的方向**（都试过，都有数字）：

| 候选判据 | 实测 | 结论 |
|---|---|---|
| 跨引擎「原版 x → Steam 句柄」绝对阈值 | 两例自相矛盾（左者一次 st03 一次 st05） | ✗ |
| 帧级相对次序（x 升序 ↔ 槽号升序） | 同序 55% / 逆序 40% | ✗ 槽号不承载位置 |
| 按原版 `index`（位号）映射 | 65% | ✗ |
| 「首出场角色 → st03」 | 完整形式 47%（只取首出场样本虚高到 94%） | ✗ |
| Steam 槽 = 角色位 | 41 个槽装了多个角色（最多 9 个族） | ✗ 槽是**句柄** |
| 按立绘名做 LCS 对齐再统计 | 同名立绘在一个脚本里重复几十次，配错实例 | ✗ |
| 按朝向分侧 | 只能解释一部分 | ✗ 很多立绘没有朝向，作者可随时安排"违反朝向"的站位 |
| 「原版 x 单独决定站位」 | 同一 x 在不同脚本落到相反侧（各 30+ 帧且内部稳定） | ✗ 不是 x 的纯函数 |
| 「按出现次序 zip 对齐两侧帧」 | Steam 侧快照数比源侧高约 2.3 倍，中途起全是错位配对 | ✗ 统计量本身是噪声 |

**两条硬限制**：① **朝向不能当判据**；② 约 1/4 组合「两侧都用」（搭档也参与决定）。
**句柄选择的作用只有一个：别撞上宿主正在用的那一个**（同句柄 → 新图顶掉旧图；不同句柄 → 两层并存），**不决定位置**。

**「换槽前清槽」必须跨块**：给某格注入的立绘可能一直挂到**后面某个骨架 `34` 才改绑同族**（此时才撞车），所以重建时不只处理**注入块内部**的 `34`，**骨架自己的 `34` 也要判**：同族还挂在另一个槽上就先补 `37`。
⚠️ **只清「注入来源」的槽** —— 骨架**原生就有**同族占两槽的场面（`backup` 全库 6 处），不加来源标记会改掉原生演出。

### 跨格拆开的引号不配对

一句台词的整对 `“…”` 被按字符切开分给多个文本框时，前格只有 `“`、后格只有 `”`，屏幕上两格**各自看着都没闭合**（全库约 93 格 / 34 个脚本）。

- **成因**：Steam 骨架把同一句拆进多个文本框（英文侧每格各带一对完整的 `\d…\d`），而官方中译给整句只写一对引号；`op:"span"` / `op:"split"` 按字符位把同一源行分到多个槽时，引号就跟着被切开了。
- **待定**：是否在前格末尾补 `”`、后格开头补 `“`（只补分隔引号、不改字）——属**标点重排**，会动到官方中译的标点位置，故未落地。
- 写盘侧口径（`\d…\d` ⇒ `“…”`）见 [localization.md](localization.md)「翻译策略」。

## 零散结论（判据与验证方法）

### 字节覆盖不构成正确性证明

反汇编器只要能在**错误的位置重新同步**，覆盖率检查照样通过；**自带发射器 + 自带解析器互相验证是循环论证**。能打破循环的只有第二实现或原生语料统计（本项目的判据是原生语料的**位置直方图**）。

**错误会被对称复制**：文档里写错的字节模板会被下游实现原样继承（第三方补丁的转换器照抄过本文档的旧写法，而它自己的 27 项回归测试全部通过 —— 因为它的发射器与解析器同样对称）。

### 判据的可靠性先于数字大小

一个 94% 但配对无保证的统计，比一个 33% 且配对唯一的统计**更不可信**。
实例：两引擎的「事件数」不同（Steam 每更新一次 `46` 就多一个快照，帧数比约 2.3:1），「按出现次序 zip」给出的 846 例、94% 强对应，换成「源侧帧唯一 → 配对强制」后同一批数据只剩 33%。
⇒ **配对方法是结论的一部分**；改用不依赖对齐的判据（族指纹、帧内集合、留出法）后结论才稳定。

### 先找同引擎的官方样本（但拿到自身样本就先用自身）

「实测优先」之前先问：**这个机制在同引擎的别的游戏里长什么样**。名字替换表的规则就是从 A Sky Full of Stars 的**官方简中包**对照出来的（前提是有一份**未加密的同引擎 exe**：CC 自己的 `.text` 段加密，ASF 仅差 0.01 版本且明文，结论可直接外推）。但**有明文样本也别放弃静态分析**：本项目的「脚本内窄字节 = CP932」与「表键必须等于脚本标记」两条关键结论都来自逆向。

⚠️ **反过来也成立：跨作证据不能当定案**。同引擎样本给的是**假设**（它的枚举/门控可能与本作不同），**自身样本才能定案**。例：`01` 的操作数布局与分支极性 —— 同引擎参考工具用 `mode ∈ {2,128,129,130,192}` 做门控，而 CC 用的是 `{2,3,128,129,130,133}`，直接照搬就会读错字节数；只有在 CC 自身 `AdvHD.exe`（脱壳后）直读它的操作数格式表与 `0x01` handler 才算证过。⇒ **同引擎样本用于「提出假设」，自身样本用于「定案」。**

### 偏移假设必须用全区间扫描排除

「我记得应该从这句开始」在拼接脚本时不可靠；**局部匹配不是证据**（前几条看起来对也可能是巧合）。做法：**对每个候选偏移做全量比对**，只有真实偏移能让全部条目零误差。

### 二进制语义不能靠统计外推

「467/467 个取值落在我认为合法的集合里」**不是语义证明**。二进制指令要**严格**：字段类型是 u32 ≠ 它是绝对偏移；值看起来像偏移 ≠ 引擎会照它跳。

例：`01` 的 `a`/`b` 是不是「文件内偏移」，靠统计「落指令首字节的比例」只能得到**旁证**；可实施的做法是读**该 opcode 的格式表与 handler**（自身 exe 优先，其次同引擎明文样本）。统计只用于实现完成后的**回归对照**。

### 不能盲信第三方产物，也不能盲信外部复审

- **第三方声称「适用」不等于能跑**：第三方补丁未经 Steam 版实测，其还原产物的指令格式与 Steam 引擎多处不兼容，直接覆盖到游戏目录会崩溃。必须实测。
- **外部复审的正确用法是「提出假设」**，验证仍要回语料 —— 逐条采纳/驳回，没有整体接受或整体否定。
- **不要过早收窄假设范围**：连续两次同类修复失败后就应转向更基础的假设。
- **报告结论必须独立复算**（本地重建 + 逐字节比对），不直接采信第三方报告的状态码。

### 「我没看到」不等于「不存在」

最贵的一次错误：查了 `34`/`37`/`39`/`64` 之后断言「Steam 侧没有坐标字段 ⇒ 位置由槽号承载」，并用三条「验证」把它包装成结论 —— 那三条其实**只证明了「槽不是角色位」**。真相是位置一直在 **`46 MoveBackground`** 里，只是当时没去看那条指令（名字像给背景用的）。
⇒ 说「两侧表达方式不同」之前，先把指令表过一遍；**推论要标成推论**，并检查结论与证据的跨度。

### 闸的通用要求

① **通过消息必须带它实际核了多少**，**计数为 0 即视为失败**（`if n == 0: fail(...)`）；
② **失败路径不得崩**：打印非 ASCII 的脚本显式设 UTF-8，且**别在消息里用 GBK 编不出的符号**（`− ≤ ≥ ⇒ ≠ ×` 用 ASCII 写）；
③ **闸写完必须接线**（流水线 + 回归清单），否则覆盖等于 0；
④ 涉及「谁在谁之后」的判据，**模型必须照抄写盘器的发射顺序**（不能顺手用数据的存储顺序 —— 既会报假错，也会放过真错）；
⑤ **跨数据源查表要显式规范化大小写/扩展名**。

### 只读解析的隐性错误假设，第一次写回时才暴露

PNA 布局曾有两版互斥的切法（「头 0x24 + 末条 24 字节」与「头 0x14 + 均匀 40 字节记录」），覆盖同一段字节、**都能逐字节往返**。第一版在只读阶段从未报错——错误字段没人消费，读出来只是静静躺着；补写回能力后靠逐字节往返回归抓出了它的假字段写入，但往返修好不等于语义正确：第一版把记录 0 的字段当头部「未知值」、每条记录的 x/y 读到下一条记录头上。定案靠的是与切法无关的独立不变量（box_w/h == 内嵌 PNG IHDR、贴图位置落在画布内）：记录表从 0x14 起每条均匀 40 字节，**没有「末条缺尾随 16 字节」这回事**（见 [engine-mechanics.md](engine-mechanics.md)「PNA 二进制布局」）。
⇒ **「只读不出错」不证明解析正确** —— 错误假设可以一直藏在没人消费的字段里；**逐字节往返一致也不证明语义正确** —— 写回前 `serialize(parse(blob)) == blob` 是第一道闸，语义必须用与切法无关的独立不变量另验。
