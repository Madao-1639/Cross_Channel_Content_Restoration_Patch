# 汉化方案

## 概述

CROSS†CHANNEL Steam 版仅提供英文文本，需要实现简体中文汉化。本方案基于 Res 303 补丁的技术实现，复用已有的翻译成果。

## 核心技术

### LNG 文件机制

LNG（Language）文件是 AdvHD 引擎的文本替换机制，用于实现多语言支持。

#### 工作原理

1. **一一对应**：每个 `.ws2` 脚本对应一个同名的 `.lng` 文件
   - `CC0TOU_en.ws2` ↔ `CC0TOU_en.lng`
   - `CCA0001_en.ws2` ↔ `CCA0001_en.lng`

2. **运行时替换**：引擎运行时，lng 文件中的文本替换 ws2 中的英文文本

3. **编码方式**：lng 文件同样使用 rot6 混淆

4. **存储位置**：lng 文件与 ws2 脚本同在 Rio.arc 中

#### LNG 文件格式

从 Res 303 提取的格式特征：

```
[Header]
  uint32_t magic;      // 可能是格式标识或文本数量
  ...                  // 偏移表或索引结构

[Text Data]
  ...                  // 替换文本（编码待确定）
```

**当前状态**：格式细节需进一步逆向分析。已知：
- 使用 rot6 混淆（与 ws2 相同）
- 包含文本偏移表
- 支持中文字符（编码方式待确认，可能是 UTF-16 或 Shift-JIS 扩展）

#### 实施步骤

1. **提取 Res 303 的 lng 文件**：从 Res 303 的 Rio.arc 中提取全部 353 个 .lng 文件
2. **格式逆向**：分析 lng 文件的结构，确定文本偏移表和文本数据的组织方式
3. **编码确认**：确定中文文本的编码方式（UTF-16/UTF-8/Shift-JIS）
4. **工具开发**：开发 lng 文件的读写工具
5. **文本校验**：验证 lng 文本与游戏场景的对应关系

### 翻译来源

Res 303 的翻译来自两个来源：

1. **主线剧情**：复用 [CROSS†CHANNEL 中文化项目](https://github.com/MewX/cross-channel_chinese-localization_project)（MewX 等）的官方译文
   - 质量较高，人工翻译
   - 覆盖主线剧情

2. **Steam 版新增内容**：7 条角色线与后日谈由 Res 303 作者用 GPT-5.6-sol 翻译
   - 机器翻译，质量待评估
   - 可能需要人工校对

### 翻译策略

1. **直接复用**：完整复用 Res 303 的 lng 文件（353 个）
2. **质量评估**：测试时评估翻译质量，标记需要改进的部分
3. **增量更新**：后续可根据用户反馈逐步改进翻译

## 字体处理

### 问题描述

Steam 原版字体不支持汉字显示，需要替换为支持中文的字体。

### 字体文件

**Steam 原版 Fonts.arc**：
- `FOT-MatissePro-B.PTF`（粗体）：7.6 MB
- `FOT-MatissePro-M.PTF`（中等）：7.0 MB

**Res 303 Fonts.arc**：
- `FOT-MatissePro-B.PTF`（粗体）：18.5 MB
- `FOT-MatissePro-M.PTF`（中等）：18.5 MB

**文件大小增加**：约 2.6 倍，说明扩展了字符集以支持汉字。

### PTF 格式

PTF 可能是 AdvHD 引擎的自定义字体格式（类似 TTF/OTF 的封装）。

**处理方式**：
- 直接复用 Res 303 的字体文件
- 无需重新制作字体

### 实施步骤

1. **字体文件替换**：用 Res 303 的 Fonts.arc 替换 Steam 原版
2. **显示测试**：测试中文字符显示效果
3. **性能评估**：评估字体文件增大对加载速度的影响

## 技术难点

### LNG 格式逆向

**挑战**：
- 格式未公开文档
- 需要逆向分析二进制结构
- 文本偏移表的计算规则

**解决方案**：
- 分析 Res 303 的 lng 文件样本
- 对比 ws2 和 lng 的文本对应关系
- 使用十六进制编辑器查找模式

### 中文编码处理

**挑战**：
- 确定 lng 文件中中文文本的编码方式
- Shift-JIS 不支持中文，可能使用 UTF-16 或其他编码
- 编码转换时的正确性

**解决方案**：
- 实测不同编码的显示效果
- 参考引擎对 UTF-16 的支持情况
- 逐字节分析编码模式

### 字体文件格式

**挑战**：
- PTF 格式未知
- 无法直接编辑或替换字体

**解决方案**：
- 直接复用 Res 303 的字体文件（已验证可用）
- 如需自定义，需逆向 PTF 格式
