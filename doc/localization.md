# 汉化方案

## 概述

CROSS†CHANNEL Steam 版仅提供英文文本，需要实现简体中文汉化。本方案基于 Res 303 补丁的技术实现，复用已有的翻译成果。

## 核心技术

### LNG 文件机制

LNG（Language）文件是 AdvHD 引擎的文本替换机制，用于实现多语言支持。

#### 工作原理

1. **一一对应**：每个含文本的 `.ws2` 脚本对应一个同名的 `.lng` 文件
   - `CC0TOU_en.ws2` ↔ `CC0TOU_en.lng`
2. **运行时替换**：引擎播放脚本时，把**按出现顺序数到的第 N 条文本型指令**
   的文本替换为 lng 的第 N 条（见下文"位置对应"）
3. **存储位置**：lng 文件与 ws2 脚本同在 Rio.arc 中
4. **覆盖完整性（已核对）**：`asset/Rio.arc` 的 363 个 `.ws2` 配 **328 个 `.lng`**，
   每个 `.lng` 都有对应 ws2；35 个无 lng 的 ws2 **全部是无文本的系统/动画脚本**
   （`AN_*`、`*_ANIME_ERASE`、`EVRET`、`LAYER_ORDER`、`mainmenu`/`title`/`start` 等，
   实测 `0x14` 计数均为 0）；每个含文本的 ws2 都有配套 lng
5. **就地插入后宿主 lng 必须整体重建：插入段的对话插进宿主中间，`keep` 之后的
   全部位置都变了，lng（位置对应）随之整体重建。**现由 `script/apply_text_map.py` 按
   `resource/text_map.json` 一次产出**（原 `script/build_host_lng.py` 已废弃 ——
   它只写 `.LNG`、输出必被覆写）。验收条件：lng 条数 == 该脚本的 `14` 条数。
   注意这 12 个宿主都**没有 `0f` 选项表**，所以「池位置」就等于「`14` 出现序」；
   若有选项表，lng 条数还要加上选项条目数（见上文「位置对应」）。

#### LNG 文件格式（`tool/lng.py`）

```
[Header]
  uint32  count                 // 条目数
  uint16  length[count]         // 每条的字节长（含结尾 NUL 对 00 00）
[Payload]
  count 条字符串背靠背，无对齐填充
```

- **单条字符串 = UTF-16LE 编码，每字节再 XOR 0x2C**。容器本身**不做 rot6**。
- 终端 `%K`/`%P`/`%N` 等控制标记以普通文本形式随条目携带（如 `终于说出话来。%K%P`）。
- 工具：`tool/lng.py` 提供 `parse_lng` / `encode_lng` / `parse_ccs` / `strip_speaker_wrap`，
  全量可解析、往返编码一致。

#### 匹配机制：位置对应（对还原管线至关重要）

- lng 中**没有 id 字段**。引擎按播放顺序把第 N 条文本替换为第 N 条目。
- **严格等式：`lng 条数 == `14` 条数 + Σ(0f 的 count)`**。`14` 与 `0f` 的每个条目**各占一个
  槽位**（一张 `0f` 表的 `count` 个选项条目各占一槽，`strid` 即槽位序），不是整张表占一槽；
  占位行（`%N`/`%P`）同样消耗条目。
  **全量核对已通过** —— `script/final_verification.py` 的 `check_lng_pairing()` 对 328 个
  配对逐一验证条款等式，无一例外。
- **lng 与 ws2 的池位可能整体错开**：Res303 的 lng 是按**汉化组 CCS 的行序**抄的，
  而 CCS 会把一句英文拆成两行中文。现由 `script/apply_text_map.py` 按
  `resource/text_map.json` **一次产出**结构 + lng：同一行的拆分记为 `span`（同一格取该行中文的
  字符片段，**不新增槽位**）。早期的 `script/realign_lng_to_ws2.py`（DP 对齐、会插 `15`+`14`）
  已废弃，详见 [localization.md](localization.md)「lng 池位错位」。
- **说话人名（`0x15 %LC<Name>`）不经 lng 替换** —— 条目数核对证明 lng 只覆盖 `0x14` 与
  选项文本。人名走**另一条通路**：引擎拿 `%LC<英文名>` 去查 `Rio.arc` 里的
  `NameTable.txt`（UTF-16LE）。详见下文「角色名称映射」。
- **对还原管线的影响**：位置对应意味着 ws2 的对话流一旦增删，既有 lng 全部错位。
  就地插入后宿主的位置全部改变，配套 lng 必须**整体重建**（见下文实施步骤 5）。

#### 汉化实施步骤

1. ✅ **格式逆向与编码确认**：UTF-16LE 后整体 XOR 0x2C（`tool/lng.py`）
2. ✅ **工具开发**：`parse_lng` / `encode_lng` / `parse_ccs` / `strip_speaker_wrap`
3. ✅ **池位对齐**：328 个配对全部满足 `lng 条数 == 14 条数 + Σ(0f 的 count)`；
   Res303 遗留的漏行 / 错位现由 `script/apply_text_map.py` 按表一次产出修正
   （`fix_lng_alignment.py` / `realign_lng_to_ws2.py` 已废弃）
4. ✅ **宿主 lng 重建**：就地插入后宿主 lng 整体重建 —— 位置对应 ⇒ 其后条目全部错位。
   现由 `script/apply_text_map.py` 按 `resource/text_map.json` 一次产出
   （原 `script/build_host_lng.py` 已废弃），规则见
   [wsc_to_ws2_conversion.md](wsc_to_ws2_conversion.md) §3.1
5. ⏳ **语义抽查**：抽样核对 lng 条目与场景对白（Res303 自述的 6 条错配已修复）

### 翻译来源

Res 303 的翻译来自两个来源：

1. **主线剧情**：复用 [CROSS†CHANNEL 中文化项目](https://github.com/MewX/cross-channel_chinese-localization_project)（MewX 等）的官方译文
   - 质量较高，人工翻译
   - 对照文本为汉化组逐行译文（293 个同名 `.CCS` + `TXT/` 下的纯中文 `.TXT`）：
     - **格式**：293 个 `.CCS` 文件（`CCA0001.CCS`、`CCC0000.CCS` 等，与原版 WSC 脚本同名对应；`TXT/` 子目录另有 293 个同名 `.TXT` 为纯中文译文，**GBK** 编码，内容与 `.CCS` 的 `>1●` 中文行一致）`.CCS` 为 UTF-16LE + CRLF 纯文本，日中逐行对照：
       ```
       >0○0001○最古の記憶は。          ← 0 行：日文原文
       >1●0001●最久远的记忆，          ← 1 行：中文译文
       ```
     - **编号关系（已全语料验证）**：CCS/TXT 的 `NNNN` = **原版 WSC 对话 id + 1**。41,629 句中 41,628 句逐字匹配、顺序完全一致（唯一差异是 CCA0002 一行 staff-roll 的空白），详见 [wsc_to_ws2_conversion.md](wsc_to_ws2_conversion.md) 「字节覆盖不构成正确性证明」。
     - **用途**：lng 文本校对信源；转换器产物的配套 lng 可按 `CCS 序号 = 对话 id + 1` 直接从 CCS 的 `>1●` 行逐句生成
2. **Steam 版新增内容**：7 条角色线与后日谈由 Res 303 作者用 GPT-5.6-sol 翻译
   - 机器翻译，质量待评估
   - 可能需要人工校对

### 匹配逻辑总览

**目标**：让屏幕上每一格显示**原版那一句的官方中文**；只有原版确实没有的格才新译。

#### 基准与不变量

- **位置对应**：引擎按播放序替换 —— lng 第 N 条 ↔ 脚本里第 N 个**占位**
  （`14` 与 `0f` 的**每个条目**都占位）。严格等式：`lng 条数 == 14 条数 + Σ(0f 条目数)`。
- **不改跳转、不加 Steam 没有的演出**；**删格只在下列「方针」判据成立时发生**。
- **原版数据是权威信源**：源 WSC（日文正文）+ 民汉 CCS（官方中文）。
  ⚠️ **`CCS 行号 == 源 WSC 的对话序 + 1`**（全库 41,629 条 100% 吻合），
  **不是 `id + 1`** —— `id` 在部分脚本里有跳号（`CCB2007` 走 0..110 却只有 109 条对话）。

#### 五条判据，由强到弱

| # | 判据 | 性质 | 产出 |
|--:|---|---|---|
| 1 | **硬下标**：Steam 格的正文就是原版日文、且在本脚本 CCS 内**唯一命中** | 定义性 | 直接取该 CCS 行 |
| 2 | **语音锚点**：格上挂了配音 ⇒ 用**时长指纹**（末页 granule ÷ 采样率，与编码无关）认出原版录音 ⇒ 原版 WSC 里该录音**紧随**的那条对话 ⇒ CCS 行 | 机械（客观可验证） | 相邻两锚之间「槽位数 n ↔ 行数 m」，`n == m` 即机械确定（实测 91.6%） |
| 3 | **区段判定**：两侧硬下标之间，按「每行用且仅用一次、**顺序不变**」逐格判 | 语义（单独判） | `n ≠ m` 的区间交判定 |
| 4 | **选项配对**：`TXT/*.TXT` 的非选项行与 CCS 中文列**逐行一一对应**；选项块按「末项是否导航项」区分同级分页与分级菜单 | 机械 | 选项译文 |
| 5 | **新译**：以上都判为「原版没有」的格 | 语义 | 必须新译（不可回落到现成中文） |

#### 定位「原处」（某句出处存疑时）

某格正文**出处存疑**（不在任何 CCS 行里、又判不出是改写还是新增）时，用**它两侧"挂原句"的格**定出原处：

> 左邻格承接的原版行号 → 右邻格承接的原版行号，**这个区间就是本段的「原处」**。

区间内的原版各行就是判据（Steam 这一句是在改写其中哪一行、还是另有新写）。**不要拿整库搜关键词** —— 同一段落在跨脚本/姊妹场景里常有重复写法，搜出来的不是本段的那一行。已用它定案过：`CCA0015_EN` 槽139 的「我回头一看…」与 `CCB1004_EN` 槽19 的同一句，原处都是「擦眼镜→看见内裤→睡迷糊→大腿」那一拍（原版行 128–136 / 12–17）。

#### 每格的动作（`text_map.json` 里 `action` 的取值）

| 动作 | 含义 | 中文来源 |
|---|---|---|
| `keep` | 取原版某一行（`rows` 给出） | 该 CCS 行的官方中文 |
| `split` | 与邻格共用一行，按**英文分句点**切开 | 该 CCS 行的**片段** |
| `opt` | 选项 | 官方 TXT 的选项译文 |
| `translate` | 原版没有 | **新译**（或取自既有译文，见下） |

#### 判据分层（阈值兜底一律清除）

| 层 | 判据 | 例 |
|---|---|---|
| **定义性** | 逻辑上不可能 | 行号越界、拼接后与原行不符、行序回退、组内无锚定格 |
| **机械性** | 客观可验证 | 时长指纹精确相等、逐字符相等、行序不减 |
| **语义性** | **一律交 subagent 单独判** | 切分点、新增/改写、孤儿行归属、锚点同一性、菜单结构 |

#### 范围

原版覆盖**整条主线**（共同线 + 循环/分岐章节 + **全部 6 条个人线** + 终章）——
**293 个脚本 / 41,924 格**；Steam 追加的是**角色后日谈与追加剧本**（35 个脚本 / 13,388 格），
边界见 `resource/original_scope.json`。范围内的文本由本项目匹配；范围外的沿用既有译文。

#### 落地形式

判定结果固定为 **`resource/text_map.json`**（每脚本一份，以 Steam 槽位序为准）——
它是写盘的**唯一依据**，见该文件头的说明。

#### 方针

1. **只针对 Steam 与原版共有的脚本**（293 个）。Steam 新增脚本（35 个：7 条角色线 + 后日谈）**完全保留**，不做结构改动。
2. **最终效果 = 并集，交集用原版覆盖**：
   - 原版有、Steam 删了 → **还原**；
   - Steam 新增、原版没有 → **只要与所匹配的原版上下文很好地吻合，就采用**（保留 + 就地翻译）。判法：

     - **符合语境 ⇒ 采用**：读下来连贯、不矛盾、不重复、能接上原版前后文。
       **成段的「加演」——在原版场景里展开的演出扩展，只要读得通，就采用**；
       **场景节奏与原版不同（更长、多几拍）不构成删除理由**。
     - **「插话」⇒ 删**：把内容塞进一个**原本连贯的语义单元**（排比、问答对、同一句话的延续）**中间**，
       使该单元断裂 —— 即便单看读得通，也**破坏了语义连贯性**，不算符合语境。
     - **仍然一律删除的两类**（即使读得通）：① **对"略过/删减部分"的交代**（Steam 给自己删掉的内容打的圆场）；
       ② **对 H 内容的改写**。
       ⚠️ 排除项②**只限于"改写"**（把既有内容替换掉）；**在原版之上"加写"新演出不算改写** ——
       加写按上面的判据走（读得通即采用，**H 加戏也一样**）。
     - **定序与定内容一律以原版为准，包括定序依据**：Steam 那一段的**英文序列**可能与**原版行序列整体错开**（"挪位"），
       **英文不得作为定序或对位的依据**。
   - 两边都有 → **用原版的文本**；
   - **不因"看起来多余"而删格** —— 删格只在上面那两类排除（交代／H **改写**）或「插话」成立时发生。
3. **语音与台词语义完全对应**。
4. **语音被切分 ⇒ 台词也切分**，切分点取**英文台词的分句边界**。
5. **引用同一语音的文本，台词必须一致**（主要适用于跨姊妹场景）。

#### 不处理（已明确排除）

- **51 处 Steam 悬空语音引用**：`asset` 与 `backup` 的悬空引用完全相同（同一 7 个脚本、同一 51 个文件名），**我方新增 0 处**，是 Steam 原档自带；且全部落在还原范围之外（`CCE0001` 45 处、`CC_22D` 1 处、`CC2KIR` 1 处、其余 4 脚本各 1 处），玩家侧仅表现为该格无声音。
- **`AN_001S.PNA`（Steam 原生死脚本）**：`asset` 与 `backup` 的 `AN_001s.ws2` **逐字节相同**，其中有 `34 AN_001S.PNA`；但 Steam 出厂三个归档（`Graphic`/`Chip1`/`Chip2`）**都没有这个文件**，且**没有任何脚本调用 `AN_001S`**（全库只有 `AN_001` 被 `CCA0002_EN`/`CC_30A_EN` 用 `0x04` 调用）⇒ **不可达死脚本，悬空引用永不执行**。原版 WSC 语料里也没有 `AN_*`（这批是 Steam 独有）。判定口径同上：asset 与 backup 完全相同 ⇒ 我方新增 0 处。

### 语音与角色名：必须与「出处台词」严格一致

**验收标准**：一格显示的**语音**与**角色名（名字框）**，必须与**该格正文的出处**一致 —— 正文取自哪，音与名就跟哪。

| 该格正文的出处 | 语音 | 名字框 |
|---|---|---|
| **原版直接汉化**（Steam 保留了原版这句） | **Steam 的**（同一句的录音，只是采样率 / 命名不同） | 原版该行的 `[話者]` |
| **Steam 切分**（Steam 把原版一句的录音切成多段、各配一段英文） | **Steam 的切分段**（一段对一段） | 原版该行的 `[話者]` |
| **原版被删减**（Steam 删了这句、连带录音） | **新增原版录音** | 原版该行的 `[話者]` |
| **原版该行本就无配音** | **无语音**（与原版一致） | 原版该行的 `[話者]`（旁白 ⇒ 清空） |
| **自译 / Steam 自有**（`op=text` 等） | Steam 的 | Steam 的 |

**实现**（全在写盘器 `script/apply_text_map.py`，随表逐格推导，不靠人工补表）：

- **名字框**：`expand_script` 按该格源行的 `[話者]` 生成（经 `speaker_map` → `%LC<英文名>`；旁白 ⇒ 清空；复合 / 集体名 ⇒ 用集体名），`rebuild(..., vc=…)` 改写紧邻该格的 `15`；
- **语音**：
  - 「原版该行无配音」⇒ `rebuild(..., del2e=…)` **删掉**该格的 `2e`；
  - 「原版有配音却没挂」⇒ `rebuild(..., plan2e={占位序: 文件名})` **补挂**一条 `2e`（`mk2e`）；
  - **补挂的选段**由 `script/gen/build_voice_plan.py` 生成 `resource/voice_plan.json`：**时长指纹只用来找候选，定案看台词**（候选录音在 Steam 侧绑定的那一格，其显示中文须与本格**逐字相同**）；
  - **要新增的原版录音**：`resource/original_audio.json` 记「原版每一行有没有配音」（WSC 的 `0x23`）；缺的录音从原版归档导入 `asset/Voice.arc`；
- **删格 = 删整格**：`drop` 去掉该格的 `14`，**连同它的设名 `15` 与清框 `15`**（`drop_units()`，
  带「**不改动任何存活格名字框**」的守卫 —— Steam 里两格之间有时只有一条 `15`，单看位置认不出归属，
  所以逐条试删、会改名字框的就留下）；该格挂的 `2e` 也**一并删**（否则语音会"漂"到下一格）；
- ⚠️ **切分格一律用 Steam 的切分段**，不许按"整行"处理。

> **两条必须记牢的事实**：① **语音与台词是严格绑定的** —— 两版里录音都紧邻它那一句，
> 所以「录音 ⇒ 那句话」唯一确定；② 时长相同**只能提供候选**（不同录音同长很常见），必须再核台词。

> ⚠️ **已废弃的路子**：「某格缺语音 ⇒ 从 Steam 的池子里挑一段**同长**录音挂上去」。
> 实测该分类 177 条里 **154 条是假象**（那些格在 Steam 原档里**本来就有语音**），
> 而且挑出来的候选**连角色都错**（时长碰撞 ⇒ 挑到别的角色的录音）。
> **正解只有两分**：原文出自原版但 Steam 保留了这句 ⇒ **用 Steam 那句的**；
> Steam 把原版这句删了 ⇒ **新增原版录音**。不存在"借同长录音"这条路。

**切分行的语音归哪一片**：

- **一行切成「台词 + 译注/注释」** ⇒ 语音只属于**台词那一片**（`※…`、`（译注…）` 不是被念的，**不挂**）；
- **一行切成多句台词** ⇒ 语音属于**句首那一片**（`2e` 紧邻句首的 `14`）；
- Steam 若本来就把该行的录音**切成多段**（各配一句英文）⇒ **每段各挂一片**（照 Steam 的切法）。

> 因此判据是「**这一片是不是这句话的起点**」，**不是**「该行有配音 ⇒ 每一片都要有」——
> 后者会把译注片和后续片都挂上，反而造成音文不符。

### PTF 格式（已部分识别）

PTF **不是纯自定义黑盒**：对文件主体做逐字节 XOR 0x2C 后，偏移 5 处出现
OpenType/CFF 的 **`OTTO`** 签名，其后 `numTables=15`、`searchRange=0x80` 与
OpenType 头部字段吻合，表目录区域可见 `BASE`/`CFF `/`GPOS`/`GSUB`/`VORG`/
`cmap`/`head` 等标准表标签。即 **PTF ≈ 5 字节自定义前缀 + XOR 0x2C 混淆的
OpenType 字体**；封装细节（前缀语义、表目录未完全对齐）未逆向完毕。

**处理方式**：
- 直接复用 Res 303 的字体文件，无需自制
- 如需自制中文字体，可按上述封装思路打包 OpenType 后实测

### 角色名的实现方式：`NameTable.txt`

**结论：角色名走引擎的名字替换表，不改 ws2 字节。**
表是 **UTF-16LE**，任意简体字都能写 —— 完全绕开脚本内窄字节的 CP932 限制。

**该表由 `resource/speaker_map.json` 生成**（`script/build_nametable.py`，已接进
`script/build_patch.py` 末步），不再是手工维护的资产 —— 这一条很重要：先前它承自上游补丁、
只由 `script/fix_nametable_prefix.py` 就地改前缀，而该脚本**不在流水线里**，
bootstrap 重建一次就会把前缀与中文名一起丢掉。详见 `resource/README.md`。

机制、格式与判定依据见 [engine-mechanics.md](engine-mechanics.md)「名字替换表」与
[engine-mechanics.md](engine-mechanics.md)「名字替换表」。要点：

- 脚本里 `15 %LC<英文名> 00 00` 的 `%LC` 是**引擎命令标记**；引擎拿 `%LC<英文名>`
  去查 `Rio.arc` 里的 `NameTable.txt`，命中就替换成表右列。
- **表键必须与脚本标记一致** —— ASF 官方简中即如此（脚本 `%LF` ↔ 表 `%LF`）。
- 本项目资产里那张表承自 Res 303，73 行**键是对的**（与脚本 73 个 `%LC` 名字
  一一对应、零偏差），**但前缀写成了 `%LR`**，与脚本的 `%LC` 对不上，引擎查不到 ⇒
  名字框一直显示英文。前缀已由 `%LC` 前缀写入时天然修正。
- ⚠️ **「键对」不等于「值对」**：该表的中文列与汉化组 CCS、与台词正文有多处矛盾
  （35 处与另两份表不一致），其中含两个角色撞名（`Matron` 与 `Lunch Lady` 都写成「食堂阿姨」）
  与两处与台词自相矛盾（`Mimimi` 写成「美美美」而台词是「咪咪咪」；`Akira` 写成「明」
  而台词是「阿基拉」）。**35 处已逐条判定，11 处改动**（依据见 `resource/speaker_map.json` 的 note）。

**为什么不能让 `%LC` 直接写中文**：引擎对**脚本内窄字节**按 **CP932** 解码
（见 [engine-mechanics.md](engine-mechanics.md)「文本编码路径」），
简体专用字（见/雾/贵/樱/游/纱/师/长/丰/咪…）不在 CP932 里，写不进去。
所以文本汉化必须走宽字符通路：正文/选项走 `.lng`，人名走 `NameTable.txt`。

字体侧无碍：Res303 替换的 `Fonts.arc` 配 `CharSet = GB2312_CHARSET` 已能渲染简体 ✓
