# 调用链组织

## 脚本命名规范

### CROSS†CHANNEL 脚本命名

**格式**：`{PREFIX}{编号}{分支}_{语言}.ws2`

**示例**：
- `CC0TOU_en.ws2` - CC0 章节，TOU（透）线，英文版
- `CCA0001_en.ws2` - CCA 章节，第 0001 场景，英文版
- `CCB1014D_en.ws2` - CCB 章节，第 1014 场景，D 分支，英文版

### 章节前缀

| 前缀 | 说明 |
|------|------|
| `CC0-CC6` | 主要角色线（TOU/MIS/KIR/MIK/YOU/TOM/SAK）|
| `CCA` | A 章节场景 |
| `CCB` | B 章节场景 |
| `AN` | 特殊场景（动画、过场） |
| `BG*_ANIME` | 背景动画 |

### 后缀含义

| 后缀 | 说明 | 数量 |
|------|------|------|
| `_en` | Steam 原版脚本 | 363 个 |

**本补丁不新增脚本名**（见下「就地插入接线」）：沿用 Steam 原有的 363 个脚本名，
内容就地改写。历史上 Res303 引入的 `CNR###_en.ws2` 还原脚本系列已全部退出。

### 分支标识

场景编号后可能带分支标识符：
- `CCA0005A_en.ws2` / `CCA0005B_en.ws2` - 同一场景的不同分支
- `CCB1014A_en.ws2` / `CCB1014B_en.ws2` / `CCB1014C_en.ws2` / `CCB1014D_en.ws2` - 四分支场景

## 脚本类型分层

**本补丁只有一类脚本**：Steam 原生 `*_en.ws2`，其中 12 个被就地插入了原版内容。

| 类别 | 数量 | 说明 |
|------|------|------|
| 未改动 | 351 | 与 Steam 原档逐字节相同 |
| 就地插入 | 12 | 见下表；出口保持 Steam 原档不变 |
| 还原脚本 | 0 | `CNR###` 系列已全部退出 |

## 就地插入接线

### 问题

Steam 删除 H 场景时，会把该场景压成**删节版**留在宿主脚本里（实测宿主是**按序跑完整场**的，
H 段被压成零头）。Res303 把完整的还原脚本追加在宿主末尾，于是宿主先播完整场删节版、还原脚本
再完整播一遍 —— **顺序倒置 + 局部重复**（详见 [lessons-learned.md](lessons-learned.md) §18）。

### 统一形状

```
宿主脚本 = [前段：Steam 原生，源 0 .. 接缝]
         + [插入段：源 WSC 的删除区间转换后**就地插入**]
         + [出口尾段：Steam 原档「末句对话之后」的字节，含原出口]
```

**不引入新脚本名、不增加跳转、不删除 Steam 内容**。工具：`script/splice_restoration.py`。

### 判据

```
lo     = 接缝 + 1   （接缝 = 宿主忠实内容覆盖到的最后一个源序号）
hi     = 交接点      （= 下一个承载本场景的 Steam 脚本的源起点 − 1；无后继则 = 场景末句）
lo_eff = lo + 首端重合长度
```

- **接缝**与**交接点**由「源 WSC ↔ 宿主 lng ↔ CCS」三方对位定出
  （`python script/audit_coverage.py --res303`，结论与 Res303 `docs/report.json` 的
  `source_range` **11/11 逐值一致**）。
- **对位只能用显示文本**。语音名 / 立绘名 / 背景名三个结构锚点**实测全部不可用**：
  Steam 侧语音按角色全局重编、立绘被重编（原版 `TCMM0002C` ↔ Steam `TCMM1001C`）、
  背景与 CG 会被替换重排。
- **宿主句数不能当上界**：`CCC0000` 宿主 211 句覆盖原版 195 行 —— 删节时会**增加**行
  （`%N`/`%P` 控制句）。

### 合并规则

**只处理插入段「首」「尾」两端的重合**；中间一律保持插入段连续，不做逐块插花。
一旦发现中间出现重合，说明接缝定错了，要回头修接缝而不是就地合并。

两端重合处逐句判「内容是否完全一致」：

- **一致** → **保留 Steam 原生指令**，把插入段对应的那几句裁掉（降低出错几率）
- **不一致** → **用原版还原**

「内容完全一致」的判据 = **中文对位的长连续块（≥5 句）**。删节区的对位会碎裂，只有长连续块
才能当证据；碎裂区一律判为不一致。

### 插入点与插入段边界

1. **插入点一律落在宿主「第一句对话之前的那个 `15`」上**。宿主第一句对话之前是**场景开场件**，
   不属于插入段、必须原样保留：
   - `CCB2101_en`：`载图 SGCC0020.PNG` + `0b id=1233/1482`（鉴赏钩子）
   - `CCC0000_en`：`载图 SCENETITLE004.PNG`；`CCD5001A_en`：`SCENETITLE011.PNG`
   - 源 WSC 对应位置是 `0xe0` 章节标题，转换器会跳过 ⇒ 覆盖掉就丢了。
2. **插入段终点**：`hi` 是场景末句时，取到该句之后、`ff` 之前的场景末尾事件（等待 / 停 BGM）；
   `hi` 是**交接点**时只能取到该句末尾 —— 否则会一路吞到文件尾、把后继脚本的内容也搬进来。
3. **插入部分横跨两个脚本时，全放在前一个脚本的末尾**（`CCD5001`），后一个脚本只做
   「去掉与插入段重合的头部」。

### 末尾跳转的处理

**宿主保留 Steam 原档的出口集合**（从 `backup/Rio.arc` 取「末句对话之后」的字节），
所以 12 个宿主改完之后出口与 Steam 原档**逐一致**：

| 宿主 | 出口 |
|---|---|
| `CCA0025C_en` / `CCB1014C_en` | `CCA0029_EN` / `CCB0020_EN` |
| `CCB2013_en` / `CCB2101_en` | `CCB2014_EN` / `CCB2019_EN` |
| `CCC0000_en` | `01 mode=0x85` + `CCC0001_EN` / `CCC0002_EN`（条件双出口）|
| `CCC3027_en` / `CCC4022_en` | `CCC3028_EN` / `CCC4023_EN` |
| `CCD0022A_en` / `CCD1001B_en` | `CCD0000_EN` / `CCD1001C_EN` |
| `CCD4003A_en` | `CCD0023A_EN` |
| `CCD5001A_en` / `CCD5001B_en` | `CCD5001B_EN` / `CCX0001_EN` |

`CCC0000_en` 的条件双出口是**唯一**带文件内偏移的出口：`01` 的 `b` 字段指向
`07 CCC0002_EN`，必须按新布局重算（`script/splice_restoration.py` 已处理并回读校验）。

### ACCEPTANCE

`script/audit_inline.py` 是回归守卫：要求每个场景与源 CCS 对位后
**恰好一次、无缺失、无重复、无倒序**，且出口等于 Steam 原档。

## 调用链完整性

### 检查策略

1. **出口一致**：12 个宿主的 `07` 集合必须与 `backup/Rio.arc` 的同名脚本逐一致。
2. **无悬空引用**：所有跳转目标脚本必须存在。
3. **顺序对位**：插入段与源序列的合并播放序必须是「恰好一次、无缺失、无重复、无倒序」。

### 检查方法

```bash
python script/audit_inline.py            # 顺序对位 + 出口一致性
python script/audit_coverage.py          # 覆盖区间（插入前用它定 lo/hi）
python script/final_verification.py      # 全量验收
```

## 资源配对保证

### 引用名 -> 归档成员

就地插入会引入**原版**的资源名，必须换成补丁里真实存在的名字
（`script/build_rename_map.py` 生成，逐条与归档成员核对过）：

| 类别 | 规则 | 落到哪 |
|---|---|---|
| 事件 CG | 原版基号 → 当前 `EVCC9XXX` 编号（按内容哈希反查，变体字母保留） | `Chip2.arc` |
| 立绘 | `TC{角色}0{nnn}{变体}` → `TC{角色}1{nnn}{变体}` | `Graphic.arc` |
| 背景 / 蒙版 | 原名 | `Chip1.arc` |
| 语音 | 原名（原版语音名，Steam 侧未重编） | `Voice.arc` |
| BGM / SE | 原名 | 游戏安装目录（不在本项目分发的归档里）|

**扩覆盖范围要补资源**：把还原段从 Res303 的那一段扩到交接点之后，新覆盖的句子会引用补丁里
还没有的资源。已实测补入 **186 条语音**（`script/import_missing_voices.py`，
源：`../CROSS_CHANNEL_Original/Voice.arc`）。`.soundlevel` 不需要——无包络的 OGG 照样播，
本项目已有实机验证过的先例（`YOU035A5000` 等 8 条）。

## 分支处理

### 多分支场景

同一场景可能有多个分支脚本（`CCA0005A_EN` / `CCA0005B_EN` …）。**每个分支都要独立判断**
是否需要还原：包含原版 H 内容的就地插入，不包含的保持 Steam 原样。

### 姊妹场景

同一段剧情在两章里各有一份脚本（**26 对**，编号规律 `CCA00nn` ↔ `CCB10(nn-9)`）。
两者**都可正常到达**（前一个脚本的选项表 `0f` 各有一条指向它们），所以**各自都要还原、
不能合并**。详见 [lessons-learned.md](lessons-learned.md) §16。

## 调用链验证清单

### 基本检查

- [ ] 12 个宿主的出口集合 == Steam 原档
- [ ] 所有跳转目标脚本存在、无悬空引用
- [ ] `14` 的 `id` 落在连续的字符串池序列上（无误填的 0 基序号）
- [ ] 配套 lng 条数 == `14` 条数 + `0f` 条目数
- [ ] 与源 CCS 对位后「恰好一次、无缺失、无重复、无倒序」
- [ ] `01 mode=0x85` 的 `b` 字段指向正确的 `07`
- [ ] 宿主第一句对话之前的开场件（`SCENETITLE*`、`SGCC*`、鉴赏钩子）仍在
- [ ] 还原段引用的资源都能解析（`script/build_rename_map.py` 的「找不到出处」清单为空）
