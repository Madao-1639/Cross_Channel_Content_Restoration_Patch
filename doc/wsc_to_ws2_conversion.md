# WSC (原版 WillPlus) → WS2 (Steam AdvHD) 指令集转换

本文档记录原版（WillPlus 引擎，`.WSC` 脚本）与 Steam 版（AdvHD 引擎，`.ws2` 脚本）两个指令集的全面分析结论、忠实转换规则、转换工具用法与验证结果。

- 分析日期：2026-09-03；**修订 2026-09-11**（按全语料逐指令复核修正 `28`/`1e` 尾段长度、
  `65` 参数、选项 strid 与对话正文策略；回归检查固定为 `script/verify_ws2_conventions.py`）
- 语料：原版 Rio.arc 全部 **324 个 WSC**（2.36 MB，ror2 解密）、Steam 版 Rio.arc 全部 **363 个 WS2**（rot6 解码）、Res303 的 12 个还原脚本*.WS2、汉化组 `CrossChannelCrack.cpp`
- 逐操作码证据：`tmp/wsc_analysis/opcode_table.md`（WSC 全表）、`tmp/ws2_analysis/opcode_table.md`（WS2 全表）。两个反汇编器收编为565/565 跳转目标全部落在指令边界，文本与汉化组 CCS 逐字互验 41,628/41,629）。

## 1. 工具链与结论摘要

| 交付物 | 位置 | 说明 |
|---|---|---|
| WSC 反汇编器 | `tool/wsc.py` | 线性解析；324/324 文件 100% 覆盖 |
| WS2 反汇编器 | `tool/ws2disasm.py` | 375/375 文件（363 Steam + 12 还原脚本）100% 覆盖 |
| 转换器 | `tool/wsc2ws2.py` | 每条 WSC 指令 → 等价 WS2 序列，或明确跳过并计数 |
| 批量 CLI | `script/convert_wsc.py` | 全量转换 + 结构校验 + 往返忠实性校验 + 资源核对 |
| 转换产物 | `tmp/converted_ws2/` | 324 个 `.ws2` + `conversion_report.json` |

**全量验证结果（324/324）**：

- 转换失败 0；产物经 WS2 反汇编器重解析 100% 通过；
- 对话 / 语音 / 图像 / 选项数量与原版零误差；
- **往返忠实性**：重解析产物逐句比对——每条对话文本与原版**逐字节一致**（CP932 原文直通，含 `%K%P`、ruby、`\n`），语音文件名与顺序一致，对话 id 一致；
- 资源缺口（Steam 侧没有的原版资源）全部列入报告 `missing_resources`（§7），是补丁 payload 的工作清单；转换器不虚构、不重定向任何资源。
- **约定回归检查**：`python script/verify_ws2_conventions.py`（7 项，含尾段结构、发射模板、
  对话文本/id、选项 strid、`15` 连跑），任何一项失败都说明转换器或反汇编器又漂移了。

> **"字节 100% 覆盖"不等于解析正确**。反汇编器只要在错误的位置重新同步，覆盖率检查仍会通过——
> 早期 `28`/`1e` 尾段少读 12/7 字节就是这样被掩盖的（尾段余下的字节恰好能解析成合法指令）。
> 因此凡固定长度的尾段，都要按**全语料的逐字节模态**验证，而不是只看覆盖率（§8.7）。

## 2. 文件级结构

### 2.1 混淆与归档

| | 原版 WSC | Steam WS2 |
|---|---|---|
| 字节混淆 | 每字节 **ror 2**（`tool/wsc2ws2.decrypt_wsc`） | 每字节 **rot6**（`tool/ws2.decode/encode`） |
| 归档 | 老式类型表归档（`tool/arcbuild.read_old_arc`，条目 13B 名 + 4B 大小 + 4B 偏移） | UTF-16LE 文件名归档（`tool/arcbuild.read_raw`） |

### 2.2 WSC 文件头 / 尾

- 头（301 个剧情脚本）：`8c <u16 全局脚本号 0..300> 00`，其后可选 `e0 <章节标题 CP932> NUL`；23 个系统脚本（BGM_*、MAINMENU 等）无头。
- 尾（324/324 恒定）：`0a 00`（停 BGM）+ `ff <u32 a> <u32 b>`（脚本结束）。
- 转换处理：`8c/e0` 删除（WS2 无脚本头，Steam 引擎自带路由与图形标题）；尾部 `0a 00` 删除（WS2 场景出口自身交接口音频）；`ff` 的 `b` 保留（128/192=含选项，两引擎语义一致）。

### 2.3 脚本路由的根本差异（场景切换的核心难点）

- **原版引擎按全局脚本号路由**：剧情脚本的"下一幕"不写在 WSC 里。实测 CCA0004 的选项块之后直接 `0a ff` 结束，分支由引擎按脚本号+选择结果分发； 56 个选项块中 42 个属于这种"文件尾选项"。
- **Steam 引擎要求显式跳转**：每个 `.ws2` 以 `15 00 00 | 07 <目标> | ff a b` 收尾。
- **解法**：Steam 语料就是路由 ground truth。`script/convert_wsc.py` 自动从 Steam 对应脚本（`<词干>_EN`）收割出口目标与选项分支目标注入转换。280/324 脚本有 Steam 对应物；其余（多为 Steam 重构/删除的 H 场景，恰是还原目标）输出终止型 `ff` 并标记 `exit.source == 'none'`，由调用链整合步骤（`doc/call-chain.md`）接线。转换器**绝不猜测**出口目标。
- Steam 尾部存在条件双出口（`07 A | 07 B | ff`，前面 `01 mode=0x85` 的 `b` 字段指向第二出口的文件偏移）；收割取第一个为默认出口，其余记入 `<词干>_ALT`。

## 3. 核心功能转换规则（字节级）

模板全部取自 Steam 原生语料与 Res303 实测可玩块；`<...>` 为变量段。

### 3.1 添加文本（0x41 叙述 / 0x42 对话）

```
WSC 叙述:  41 <u16 id> 00 0f <文本 CP932> 00                    （20,454 条）
WSC 对话:  42 <u16 id> 00 0f 0f <说话人 CP932> 00 <文本 CP932> 00 （21,175 条）
        ↓
WS2:      15 [00 | %LC<说话人> 00] 00            ← 清框 + 说话人前缀
          14 <u16 id> 00 00 'char' 00 <文本> 00 00
```

- **id 是"字符串池序号"**：两引擎的 `14` id 与 `0f` 条目的 strid 属于同一个按**文件出现顺序**填充的字符串池，选项文本也占槽位。所以 id 从 0 起连续递增、但**会跳过选项占用的号**（原生 CCA0006：204 句对话 id 0..203 → 选项 strid 204,205,206 → 下一句 id 207；WSC 侧的 id 序列与之逐项相同）。转换器按同一规则发射（`_Emitter.pool_index`），因此 `id` 与原版 WSC 的 id 逐项相等，可以直接给 lng 当锚点（汉化组 CCS/json 编号 = WSC id + 1）。原版最大 id 2358，不溢出。
- **正文写原版 CP932 原文**，不改写、不替换成占位符（`%K%P` 全语料 41,629/41,629 恒定收尾；`{漢字:かな}` ruby、`\n`、`%X..%XE` 等标记原样保留）。显示文本由同名 `.lng` **按位置整体替换**（原生 CCA0001_en 的 32 句 ↔ 32 条 lng 逐条对应，逐条是译文），所以脚本里的原文是 lng 缺条目时的兜底，不是占位。
- 说话人经 `SPEAKER_MAP`（§5）译成 Steam 英文名进 `%LC`；表外名字原样保留并告警。
- **配套 lng 的生成规则**（用既有正确样本逐字节反验过，0 处不匹配）：
  - lng 第 N 条（0-based）对应 ws2 内第 N 个 `0x14` 对话按遭遇顺序的位置，**不是**按 `0x14` 的 id 字段索引（位置对应，见 `doc/localization.md`）。
  - 文本来源为汉化组 CCS 的 `>1●` 行，按"CCS 行号 = WSC 对话 id + 1"取值；还原脚本若拼接了不连续的 WSC 片段，必须先用**全区间偏移扫描**确认基准行号（对每个候选偏移做全量比对，只有真实偏移能让全部条目零误差，见 [lessons-learned.md](lessons-learned.md) §4），不能凭记忆或局部匹配假设偏移。
  - 每条文本追加 `%K%P` 收尾（与对话文本惯例一致）。
  - CCS 中 `[说话人]"文本"` 整行包裹时，lng 里要去掉说话人前缀和外层引号，只留引号内文本（`tool/lng.strip_speaker_wrap`；73/364 条全篇涉及，句中引号如"随便你"不受影响）；说话人身份已由 `0x15 %LC<Name>` 承载，文本正文不重复。
  - 编码走 `tool/lng.encode_lng()`：UTF-16LE 编码后整体 XOR 0x2C（详见 §lng 格式，`doc/localization.md`），不能用明文 UTF-16LE。
  - 现行实现：`script/build_host_lng.py`；通用解析/去引号函数：`tool/lng.parse_ccs` / `tool/lng.strip_speaker_wrap`。
- 每条对话前发一条 `15`（原生 idiom：`15→14` 54,176 次）；图像块之后重开对话框层 `16 01 00`（贴近原生形态，Res303 同款）。

### 3.2 添加语音（0x23）

```
WSC:  23 00 ff ff 00 00 00 00 65 00 <you035A5000> 00        （10,693 条，前缀恒定）
   ↓
WS2:  2e 28 charCN 00 <YOU035A5000.OGG> 00 <22B 恒定尾>
      15 [前缀] 00 / 14 <id> ...                             ← 紧随其对话行
```

- 22 字节尾 = `00×10 | 0a 00 00 65 | 00×8`，全语料 15,959 条逐字节恒定（与 `28` SE 的 22B 尾同源，布局对照见 §3.6）。
- 通道固定 `charCN`（Res303 现网实测可发声；Steam 原生用 `charXXX` 角色通道，改通道牵动每角色音量设置，暂沿用，备选 `charYOU` 等整块替换）。
- **文件名 = 原名大写 + `.OGG`**。注意：Steam 的语音编号是**按角色全局重编**的（`YOU_0026.OGG…YOU_0051.OGG`），与原版场景块编号（`you026A5000`）**无对应关系**，不能直接引用 Steam 原生语音名（会播错音频）；原版语音需按原名大写补入 Voice.arc（Res303 同款做法，如 `YOU025A5000.OGG`），可经 `rename_map` 重定向。语音指令紧贴其对话行之前；后跟非对话指令时原位补发（19/10,693 例）。

### 3.3 添加 CG / 背景 / 立绘（0x46 / 0x48）

```
WSC 背景层:  46 <9B 全零> <EVCC0001 | BLACK | WHITE> 00     （CG / 遮黑遮白，1,653 条）
             48 05 ... <BGCC####> 00                        （背景）
        ↓
WS2 背景块（~106B，bg01 槽）:
      15 00 00                        ← 清框
      16 00 00 | 64 00 | 37 2a 00     ← 图层块 + 渐变标记 + 停全部动画
      33 bg01 00 <名>.PNG 00 01 01    ← 加载图像（flags 恒 0101）
      04 LAYER_ORDER 00
      09 00 0a..0d 00 00 80 3f ×4     ← 图层透明度 1.0
      46 bg01 00 <19B 全零>           ← 无补间
      65 00 00 00 <f32 渐变秒> 00000000 0200   ← 渐变（首操作数恒 0x00）
      16 01 00                        ← 重开对话框层

WSC 立绘:   48 01..04 ... <TCYM0000 | TCYM0000X 等> 00   （含 X/Z 掩码变体）
        ↓
WS2 立绘块: 34 st0<n+1> 00 <名>.PNA 00 01 01
            39 st0<n+1> 00 02 01 04 03 00 00 00 01 00 02 00
            04 LAYER_ORDER 00
```

- 路由：`0x48` 模式 05（1,250 条）或名字 `BGCC*` → 背景块（bg01 槽）；其余（模式 00/01/02/03/04，全部为 TC**/SGCC/EFCC 系）→ 立绘块。立绘槽位取最近一条 `0x64` 的槽位号 a（0..4 → st01..st05）。
- 渐变秒数取自紧邻的 `22 <u16 ms>`（ms/1000，535 条），无则 1.0（Steam 语料众数；原版个别实测另有 1.5s/0.0 等差分值，见 §9.4）；背景块后的首个 `4a <ms>` 渐变等待已并入 `65`，不再单独发。
- **不要写成 `65 64 00 00`**：原生 11,022 条 `65` 的**首操作数恒为 `0x00`**。`65 64 00 00` 是 `66` 蒙版块**自己的**那条尾部（`66 <名>.PNG 00` 之后紧跟 `65 64 00 00 <f32 1.0> 00000000 02 00`，见 §3.6）；把两处的字节混用会写出原生不存在、引擎侧未验证的参数。Res303 的还原脚本用的是 `65 64` 形态（实测可玩），但原生语料里没有先例。
- `BLACK`/`WHITE` → `BLACK.PNG`/`WHITE.PNG`（Steam Graphic.arc 实存，直接引用）。
- **CG 单独成段、并统一改名**：原版 `EVCC####` 与 Steam 同名 PNG **内容不同**（同名冲突，见 `doc/pna-resources.md`），忠实还原必须把原版 CG 以新名补入资源包，并经 `rename_map` 改写引用。新名一律落在 **`EVCC9XXX` 段**（引擎只认 `EVCC` 前缀，`CN_` 前缀会被静默忽略），编号按脚本引用顺序分配（规则见 [lessons-learned.md](lessons-learned.md) 第 9 节；具体编号对照用 `python script/renumber_evcc9xxx.py --check` 现印）。直接引用 Steam 同名文件会显示错误画面。
- X/Z 掩码变体（`TCYM0000X` 等，原版 Chip_T.arc/Chip_E.arc 独有资源）缺失进 `missing_resources`，由补丁补入。
- `0x46 CG_BACK`（31 例，"恢复上一张 CG"）无 WS2 等价指令，跳过并告警。
- **操作性警告**（`doc/lessons-learned.md` #4）：`33` 硬加载缺资源会卡死引擎——转换产物入包前必须消掉 `missing_resources` 清单。

### 3.4 场景切换（0x07 / 0x09 / 0xff）

```
WSC:  09 <cca0002> 00            （剧情链，562 条，语料实证全部位于有效文件尾）
WSC:  07 <MAINMENU/TITLE> 00     （系统脚本转移，50 条）
        ↓
WS2:  15 00 00 | 07 <CCA0002_EN> 00 | ff <u32 a=8> <u32 b>
```

- **只在有效文件尾**（其后仅 `0a/ff`）映射。语料实证原版 07/09 兼有 call-and-return 语义：`07 EVRET`（15 处）、`09 RestBGM`（14 处）、`09 CG_WAIT`（147 处）之后仍有数十条活指令（CCB1101 的 EVRET 后有 53 句台词且全文件无 06 跳转可及，只能是线性返回）。WS2 的 `07+ff` 是终止语义，无法承载中部调用——中部转移一律跳过并告警，后续内容线性保留，**零内容丢失**。
- 目标解析优先级：`transfer_target_map` 显式改写 > `<目标>_EN`（Steam 对应物）> `MAINMENU`/`TITLE`（Steam 剧本同样裸名调用的系统脚本）> 跳过并告警。Steam 的 `EVRET.ws2` 是跳 TITLE 的遗留脚本，与原版同名例程语义不同，**不可映射**。
- `ff.a=8` 为实测可玩值。原生出口的 `a` 取值
  **非常分散**：363 个脚本共 336 条 `ff`，`a` 有 **203 种不同取值**，从 `0`、`3`、`8`、`58`、
  `180` 一直到 `32884`/`32966`（`0x4000`/`0x8000` 段）。它是引擎内部参数，转换器统一取 `8`
  是一个**有意的简化**——不要因为看到 `a=16515` 这类值就认为脚本损坏。 `ff.b` 保留 WSC
  尾参语义（128/192=含选项，其余归 0）。
- 文件正常结束（`ff`）而无转移时：出口取 Steam 对应脚本收割结果；无对应物则输出 `15 00 00 | ff 8 b` 并告警，等调用链整合接线。

### 3.5 添加选项（0x02，完整支持）

```
WSC:  [前导 01/03/8e 序列] 02 <count> 00
      { <u16 sid> <文本 CP932> 00 | 01 <0x0351+i> 03 01 02 00 00 <i+1> 00 00 } ×count
        ↓
WS2:  15 00 00
      0e 0b 00 <count> 00 01
      0f <count>
      × count: <u16 strid> <文本 CP932> 00 00 <u16 label=0x0b+i> <跳转>
      跳转 = 06 <u32 输出文件内偏移>  |  07 <脚本名> 00
```

- 分支目标解析（逐选项）：① 文件内 `06` 分发阶梯（13 块，如 CCD0102 章节选择：第 i 个选项 → 其后第 i 条 `06` 的目标；输出端经两遍发射把目标重定位到新偏移）；② Steam 对应脚本 `0f` 选项表收割（50 表）；③ 不足处回退到本脚本出口并告警。
- **strid = 字符串池序号，等于 WSC 的 `sid`，不是 0 基表内序号**（池模型见 §3.1）。实证：全语料 43 个含选项的脚本，发射出的 strid 与 WSC `sid` **逐表逐项相等**；同名对 CCA0004（WSC 145 句 → sid 145,146；Steam 151 句 → strid 151,152）、CCD0102_EN（2 句 → 2,3,4,5）两侧同规则。写成 0 基会让选项文本与字符串池错位。
- **一个脚本的多张选项表逐表对应**，不能跨表复用 Steam 目标：CCB0007/CCD0007 各 2 张、**CCD0102 有 12 张**。`steam_choice_map[stem]` 是"每张表一个目标列表"的列表。
- 阶梯识别按**位置**（选项块之后第 i 条 `06`），不按条件值排序：真实阶梯 `01 {type=3, value=6}` 的条件字节 `c` 只有 3/14 处为 1、其余为 0（CCD0102 的四条是 c=1,0,0,0），按"条件里的选项序号"筛选会把真阶梯判成不完整。
- 阶梯中的 `01 var=6` 赋值体（原版"下一场景"状态变量）被丢弃并计数——WS2 选项直接跳转，无处承载该状态；仅影响 hub 型系统脚本（已文档化的语义损失）。
- 选项文本 CP932 直通（与 `14` 同为 NUL 串，字体支持同对话）；选项文本占用字符串池的 `count` 个槽位，其后对话 id 顺延。

### 3.6 其他完整映射

| WSC | WS2 | 说明 |
|---|---|---|
| `00 00 00 <SE###.ogg>` SE（523） | `28 se01 00 <SE###.OGG> 00 <22B 尾>` + `15 00 00` | 文件名大写；尾段布局见本节末 |
| `21 00 00 00` + `0a ff ff … <BGM###>`（595） | `1e bgm01 00 <BGM###.OGG> 00 <17B 尾>` + `0b <u16 1049+N> 01` | 尾段是**同一条指令的参数**（不是"10B 尾 + 一条 `0a`"）；曲目 id 规则 `1049+N` 取自原生语料（BGM015→1064，25 曲全吻合） |
| `0a 00` 停 BGM（中程，523） | `1f bgm01 00 <f32 1.0>` | 原生无 0.0s 形，取原生众数 1.0s；文件尾停 BGM 省略（出口自身交接口音频） |
| `54 <EFMSK_##> 00`（+55/74，764） | `66 <EFMSK_##.PNG> 00 65 64 00 00 <f32 1.0> 00000000 02 00` | 蒙版时长原生恒 1.0s |
| `06 <u32 绝对偏移> 00` 文件内跳转（565） | `06 <u32 新偏移>`（5B，无 WSC 的尾 00） | 两遍发射：目标指令的输出偏移记录于 labels，全部跳转可重定位 |
| `4a <mode> <ms> 00` / `82 <u16 ms> 00` 独立等待 | `11 timer01 00 00 <f32 s>` + `12 timer01 00 01 00` | 原生等待惯用形；图像块后首个 4a 已并入 `65` |

**音频三兄弟的尾段布局**（都按**整条指令**读，少读会把参数当成指令）：

| 指令 | 尾段 | 布局 | 全语料不变量 |
|---|---|---|---|
| `2e 28 <chan> 00 <file> 00` 语音 | 22B | `00×10 0a 00 00 65 00×8` | 15,959 条逐字节恒定 |
| `28 <slot> 00 <file> 00` SE | 22B | `f32 vol @0 · f32 @4 · u16 mode @8 · u16 code @10 · u8 @12 · u16 @13 · u16 @15 · u8 @17 · f32 @18` | 1556 条：`[11]==[12]==0`、`[14:17]==0`、`[18:22]==0`，`([13],[17])` 只取 `(0,1)`（SE，1248 条）或 `(101,0)`（槽名 `char*` 的语音形态，308 条）；音量/mode/code 随实例变化 |
| `1e <slot> 00 <file> 00` BGM | 17B | `f32 vol @0 · f32 0 @4 · u16 0xffff @8 · u16 0x000a @10 · u8 1 @12 · f32 0 @13` | 877 条，仅音量变化（0.0/1.0/2.0） |

- 三者同源（`2e 28` 的前缀、`28`/`1e` 共有的 `0xffff`/`0x000a` 标记都指向同一套"槽内音频"参数块），所以尾段长度必须一致地按 22/22/17 字节读。
- 转换器发射 SE 用模态形态 `00×10 0a 00 00 00 00 00 00 01 00 00 00 00`（1086/1556）。原版 WSC 的 `0x00` 指令里没有音量/mode/code 信息，只能取模态值——这不是丢失信息，是源侧本来就没有。
- 编解码侧：写死长度会两端一致地错（自带解析器与自带发射器互验通过、独立解析器才发现不一致）。**尾段长度必须用第二实现或逐字节模态核对**。

### 3.8 切片模式（就地插入调用脚本）

`tool/wsc2ws2.convert_range(wsc, stem, opts, start_offset, end_offset)` 按 WSC 字节偏移区间
转换（左闭右开，端点必须落在指令边界）。`ConvertOptions.slice_mode=True` 表示这段产物要**接在
宿主脚本中间**而不是做成独立脚本，四处行为不同：

| | 独立脚本 | 切片（`slice_mode=True`） |
|---|---|---|
| 出口 `07` / `ff` | 发射出口 | **跳过**，由宿主的出口尾段承担 |
| 文尾 `0a`（停 BGM） | 由出口交接口音频，丢弃 | **照常发射**，否则插入段结尾漏掉停 BGM |
| 开头 `16 01 00`（开对话框） | 需要 | **抑制**，宿主此时对话框已开 |
| 字符串池序号 | 从 0 起 | 从 `opts.pool_start` 起 |

`pool_start` 必须等于**前段保留下来的对话数**——`14` 的 `id` 等于文件内出现序
（实证：363 个原生脚本里 354 个满足 `id == 0..n-1`，9 个反例全是有 `0f`
选项表的脚本，见 §8 第 7 条），插入段接续这个序号才能对上池。

`start_offset` / `end_offset` 由调用方按源 WSC 的对话序列定：起点 = 接缝后第一句的偏移；
终点 = **`hi` 是场景末句时**取该句之后、`ff` 之前的场景末尾事件（等待 / 停 BGM），
**`hi` 是交接点时**只取该句末尾（否则会一路吞到文件尾、把后继脚本的内容也搬进来）。

回归保障：默认路径（非切片）的产出与改造前**324/324 脚本逐字节一致**。

## 4. 两个引擎的关键语义差异（分析结论）

1. **对话 id 两边都是 u16**——推翻旧文档"WS2 id 为 u8"的记载（id≥256 的原生
   文件实证）；`14 <id:u8> 00 00` 旧读法实为 `<id:u16> <00>`。
2. **WS2 的 `07` 无 `ff 08` 尾**——`ff` 是独立指令；旧文档把出口写成一个指令是错的。
3. **原版 07/09 兼有调用语义**（§3.4），这是场景切换转换的最大陷阱。
4. **原版选项在文件尾时由引擎路由**（42/56 块），分支不在脚本内。
5. **`ff a b` 两引擎同构**：`b=128/192` 与"含选项"强相关；`a` 为引擎内部参数（Res303 的 a=0 崩溃，取 8 修复）。
6. **语音编号体系完全不同**：原版按"角色+场景块+变体+行"（`you035A5000`）， Steam 按角色全局重编（`YOU_0026.OGG…`），二者无换算关系。
7. **Res303 的还原脚本*.ws2 不是忠实转换**：与原版 CCC0000 尾段对齐后逐句错位、文本被占位符替换（只能作字节模板与说话人名参考）。这正是需要逐指令忠实转换器的原因——把"剧情骨架正确"升级为"逐句还原"。

## 6. 使用方法

```bash

opts = ConvertOptions(
    rename_map={'EVCC0001': 'EVCC9007'},          # 资源重命名（补丁管线接入点；新名一律 EVCC9XXX）
```

## 8. 已处理过的实现陷阱（改代码前必读）

1. WS2 `15` 空前缀是 `15 00 00`（prefix NUL + 尾 00）——少一字节会把下一条 `14` 吃进 prefix。
2. 选项条目的 `06` 占位 fixup 偏移必须按条目实际长度（`len(head)`）计算，不能写常数。
3. `tool/ws2disasm.py` 的 `operands` 惯例：`14` 的 operands 从 id **高字节**开始，文本切片是 `[cend+1:-2]`（尾部含 text NUL + tail 两个字节）。
4. WSC 语料文件（`tmp/corpus/wsc/`）是**已解密**的；从归档直读时才需要 `decrypt_wsc`，不要二次解密。
5. `0x48` 的参数域在反汇编器 fields 里是 hex **字符串**（`params[:2]` 是字符不是字节）。
6. `0x34` 槽名是一个完整 NUL 串（`st01`..`st12`，全语料 tag 字节恒 `73`('s')、剩余恒 `t*`）；`tool/ws2disasm.py` 把首字节拆成 `tag` 字段、余下作 `slot` 显示，是**同一字符串的拆分显示而非两个独立字段**。发射时直接写 `34 "st%02d" 00`，若再补一个 0x73 前缀会产出非法的 "sst01"（2026-09-09 已修复并经原生语料逐字节验证）。注意 `0x34` 另有 `tag=0x40`('@') 的 `@ANIMATION_SETKEY` 形态，检查槽名时要按 tag 分流。
7. **定长尾段必须按整条指令读**：`28`=22B、`1e`=17B、`2e 28`=22B（布局见 §3.6）。少读的字节会被当成下一条指令——而尾段余下的字节**恰好**能解析成合法指令（`28` 少读 12B 时 `0a`(7B)+`01`(5B) 刚好接上），所以自带解析器的覆盖率检查照过、往返比对也自洽。这类错误只能靠**第二实现或全语料逐字节模态**发现（§1 警示框）。
8. `65` 的首操作数恒为 `0x00`；`65 64 00 00` 属于 `66` 蒙版块自己的尾巴，不要混用（§3.3）。
9. 说话人前缀按 **CP932** 编码写入 `%LC`；表外说话人是日文名，用 ASCII 会直接抛 `UnicodeEncodeError`（本语料 0 例，属潜伏）。

## 9. 已知限制与后续工作

1. **40 个脚本出口未接线**（设计行为，非缺陷）：按 `doc/call-chain.md` 的穿插方案人工接线；`exit.source == 'none'` 即工作清单。
2. **hub 型脚本选项状态损失**：CCD0102/CCD0007/CCB2007 阶梯 `01 var=6` 赋值被丢弃；若需要等价的章节选择状态，须在调用链层用 WS2 变量重建。
3. **立绘 0x48 模式 01/02/03 与 04 的显示差异**（淡入淡出/混合模式）未逐模式复刻，统一 `34+39+LAYER_ORDER`；X/Z 掩码变体资源待补丁补入。
4. **演出时序**：渐变统一 `65`（0x22 派生或 1.0s 众数默认），未复刻 `03/4a` 变量渐变的逐帧曲线；原版个别渐变实测另有 1.5s/0.0 等值，属 Steam 差分；BGM 停用 1.0s 淡出替代瞬时停。
5. **`1d` 文本框显隐辅助指令未映射**（2026-09-09 调查结论）：Steam 原生在 `16 a=0`（关对话框层）之后成对使用 `1d a=2` / `1d a=65535`（331/363 文件、各 159 处，开闭平衡；个别窗口内含 `char` 通道对话，与 `16` 的语义分工未实机验证）。原版对应物是 `03 b=996 d`（§3.7），转换器已用 `16 a=0/1` 承担显隐，故未映射 `1d`。旁证：Res303 全部还原脚本*.ws2 **均不含** `1d` 且实测可玩——缺 `1d` 不影响可玩性，仅可能丢失个别场景的窗口状态微调。
6. **原生 `14` 通道语义补充**：Steam 原生 `14` 通道分 `char`（对话，前驱必为 `15`）与空（**只承载独立成行的 `%N`/`%P` 控制句**，全语料 1,708 条无一真文本、且从不带 `15` 前驱）。原版叙述（`41`）转换后走 `15 00 00 + 14 char`（空说话人），与原生叙述呈现路径一致（CCA0001_EN idx45-54 实证）；转换器不为 `%N/%P` 生成独立空通道句，标记随正文直通。
7. **实机测试**：全部结论为静态分析 + 语料交叉验证，需按 `doc/acceptance-criteria.md` 跑通一条角色线后升级结论；说话人低置信度条目同步校对。
8. **`CNR*.ws2` 系列已全部退出**：内容改由 12 个宿主**就地承载**，插入段一律用 `convert_range` + `slice_mode` 从源 WSC 重新转换，按本节规则写**原版 CP932 原文**。`asset/Rio.arc` 现为 363 个 `*_en.ws2`，与 Steam 原档脚本数一致；`script/final_verification.py` 的 `check_inline_splice()` 是回归守卫。
9. **`2e 28` 与裸 `28` 两种语音写法并存**：原生 14,824 条写 `2e 28 <chan>`，另有 308 条直接写 `28 <chan>`（槽名 `char*`，尾段 `([13],[17])=(101,0)`）。转换器统一发 `2e 28`（多数形态）。
